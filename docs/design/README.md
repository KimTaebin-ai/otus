# OTUS 디자인 시스템

**서비스 이름은 OTUS다.** 이미지의 "42 Support"/"42 SUPPORT"는 임시 이름이라 코드는 `shared/core/brand.ts` 상수를 쓴다. 로고는 "42" 자리에 같은 굵기·색으로 "OTUS" 하나만 두고 "SUPPORT"는 없앤다. 42 학교·계정을 가리키는 "42"("42 계정으로 로그인")는 그대로 둔다.

토큰 값은 `shared/styles/_tokens.scss`에 있다. 이 문서는 규칙과 화면별 메모다. `wireframe/README.md`는 와이어프레임 시절 문서라 더는 기준이 아니다.

## 이미지 역할 (2026-10-17 결정)

- **`final/`이 기준이다.** 색, 타이포, 간격, 레이아웃, 컴포넌트 모양, 문구는 전부 final에서 가져온다. 1440px 폭, 1x다.
- **`wireframe/`은 UX 흐름 확인용이다.** 화면 순서, 화면에 어떤 정보가 있는지만 본다. 색·모양·문구는 가져오지 않는다.
- **둘이 다르면 final이 이긴다.**
- final에 없는 화면(U05 이력·보완의 재검토 요청 상태, U06 사용자 설정)은 wireframe 흐름 + final 스타일로 만든다. final에 없는 시각 요소가 필요하면 지어내지 말고 먼저 묻는다.

## 전체 컨셉

- **톤**: 밝고 차분한 화면에 강조색은 teal 하나다. 문구는 "~해요", "~해주세요" 같은 부드러운 존댓말이고, 사용자를 이름으로 부른다("동민님, 반가워요!").
- **색 쓰는 규칙**
  - `--color-teal`: 주 버튼, 활성 메뉴 글자·아이콘, 텍스트 링크("파일 고르기", "변경", "설정 →"), eyebrow, 정보 박스 제목, 아이콘.
  - `--color-mint`: 활성 메뉴 배경, 정보 박스·강조 카드 배경, 아바타, "준비 완료" pill, 승인 배지.
  - `--color-bg`: 본문 배경(셸 바깥 면), 문서 아이콘 박스, U01 안내 박스, 미완료 count pill.
  - `--color-surface`(흰색): 상단바, 사이드바, 카드, 파일 행, U02 하단 바.
  - `--color-nav`: U01 왼쪽 패널에만 쓴다. 그 위 글자는 흰색과 `--color-nav-muted`, 아이콘은 `--color-nav-link`.
  - 글자는 `--color-ink`(제목·값)와 `--color-muted`(설명·라벨·메타) 두 단계다.
  - 상태색(blue/red/amber)은 상태 표시에만 쓰고 항상 텍스트와 함께 쓴다.
  - 그림자는 없다. 흰 카드는 `--color-border` 1px 테두리로 구분한다. 민트 면과 U02 하단 바는 테두리가 없다.
- **타이포 위계** (Noto Sans KR, 추정치)
  - 로고 "OTUS" 42 bold / U01 헤드라인 40 bold / 페이지 제목 28 bold
  - U03 히어로 제목 20 bold / 카드 제목 16 bold
  - 히어로 본문·FAQ 답 16 / 라벨·버튼·메뉴·본문 14 (라벨은 medium)
  - 캡션 12(브레드크럼, 섹션 라벨, 정보 박스 본문) / eyebrow 11(teal)
- **레이아웃**
  - 페이지 머리: teal eyebrow → 제목(28) → muted 한 줄 설명. U03은 제목 오른쪽 끝에 기준 월("2026년 9월")이 있다.
  - 본문은 카드가 세로로 쌓인다. 2열일 때 오른쪽 보조 열은 372px, 열 사이와 카드 사이는 24px.
  - 카드 안쪽 여백 24, 카드 radius 16, 행·정보 박스 radius 12, 버튼 radius 6.
  - 한 화면의 주 버튼(teal)은 하나다. 보조 버튼은 흰 배경 + 테두리이고 주 버튼 왼쪽(U02) 또는 오른쪽(U03 due)에 둔다.

  - 왼쪽: teal "OTUS"(20, 이미지의 "42" 자리) + muted "/ 첫 서류 등록".

**서류 행 상태**

- 업로드 전: 설명(예: "내 이름과 사진을 확인할 수 있는 신분증 PDF") + 오른쪽 "파일 고르기".
- 업로드 후: "파일명 · 크기"(예: "신분증_동민.pdf · 1.2 MB") + 오른쪽 "변경". 행은 teal 테두리 + mint 배경이 되고, 아이콘 박스는 흰 배경에 teal 체크로 바뀐다. final ready 이미지에는 없는 강조로, 완료가 눈에 안 띈다는 피드백에 따라 넣었다(사용자 결정 2026-10-17). 화면낭독기에는 "{서류명} 업로드 완료: {파일명}"을 aria-live로 읽어준다.
- 업로드 중 진행 막대, 빨간 형식 오류 박스, 주황 전송 실패 박스는 final에 없다. wireframe(Validation states) 모양에 final 토큰을 쓴다.
- U04 final에는 "유지" 행이 없다. 기존 3종은 정보 박스 문구로만 알리고 `mode="kept"` 행은 쓰지 않는다(2026-10-17).
- U04의 업로드 영역은 이 행 모양이 아니라 final의 드롭존/mint 패널이다(아래 "U04 월별 제출"). 업로드 진행률·오류 처리 로직은 같다.
- 이력 화면의 "보기" 링크(파일 열람)는 이번 범위에서 만들지 않는다.

### 이미지와 정책이 다른 곳 (정책을 따른다)

- **발송 채널은 "서비스 알림"만이다.** 이미지의 "이메일 + 서비스 알림"은 쓰지 않는다 (메일 발송은 범위 밖). "메일 미리보기"는 "사용자에게 이렇게 보여요"(알림 미리보기)로 바꾼다. 메일 제목 "[42] 9월 서류 제출 안내"는 알림 제목으로 바뀐다.
- **알림 문구는 학생 벨과 같다**: 제목 `{M}월 서류, 준비하고 계신가요?` (`frontend/src/app/layout/notifications.ts`). 본문은 `{M}월 고용보험가입내역서를 준비해주세요.` / `{M}월 1일 이후 발급본이 필요해요.` / `{M}월 {말일} 23:59까지 PDF로 올려주세요.` 이동 버튼은 "이번 달 서류 제출하기". 말일과 마감 시각은 서버 `closes_at`을 `lastMoment()`로 표시한다.
- **발송 대상 규칙은 하나다: 미제출 − 취업 중.** 임시 저장만 한 사용자는 미제출이다. 최종 제출을 끝낸 사용자와 취업 중인 사용자는 제외한다. "40시간 달성(예상)" 같은 시간 요건 조건은 넣지 않는다 (서류 마감과 시간 집계가 둘 다 말일이라, 월중에 40시간 미만이던 사람이 말일까지 채우면 알림을 못 받아 서류를 놓칠 수 있다).
- **"대상 확정 / 대상 미확정 / 해당 없음 / 판단 보류"는 쓰지 않고 세 축으로 나눈다.** 시간 요건과 최종 수령 대상은 `docs/api-proposal-eligibility.md`의 enum 그대로다. 취업 중은 시간 요건과 별개 축(제외 조건)이다.

| 축 | 값과 화면 문구 |
|---|---|
| 시간 요건 | 월중 **집계 중** / **40시간 달성(예상)** / **80시간 달성(예상)**. 달 종료 후 **판정 대기**. 판정 후 **충족**(`met`, 구간) / **미충족**(`not_met`) / **판단 보류**(`on_hold`) |
| 서류 상태 | `STATUS_LABELS`와 `BADGE_LABELS` 그대로 (검토 대기 / 재검토 요청 / 재검토 대기 / 서류 승인) |
| 최종 수령 대상 | **확정 전**(`undecided`) / **수령 대상**(`eligible`) / **수령 대상 아님**(`not_eligible`) |

  - "달성(예상)"은 월중에만, "확정"은 최종 수령 대상에만 쓴다. 한 문장에 섞지 않는다.
  - A00 상태 카드는 학생 용어를 쓴다: 제출 대상(취업 중 제외) / 미제출 / 검토 대기(`pending_review` + `resubmitted`) / 재검토 요청(학생 재제출 대기).
  - A00 안내 박스는 "대상 100명 + 해당 없음 20명 + 판단 보류 8명" 한 줄 대신 이번 달 집계(집계 중 n명, 40시간 달성(예상) a명, 80시간 달성(예상) b명)와 지난달 판정(충족, 미충족, 판단 보류, 수령 대상 확정, 확정 전)을 두 줄로 나눠 쓴다.

### 화면 메모

- **A07 제출 안내** (`A07-notice-empty`·`A07-notice-sent`): 제목 오른쪽에 월 선택. 카드 3개(이번 달 미제출 / 취업 중 · 자동 제외 / 알림 발송 대상, 마지막은 mint)는 라벨 + 보조 문구 왼쪽, 큰 숫자 오른쪽의 가로형이다. 왼쪽 카드 "발송 대상 n명"(사용자 / login / 취업 / 상태 배지 표, 0명이면 체크 아이콘 + "지금은 안내할 분이 없어요"), 오른쪽 카드 "사용자에게 이렇게 보여요"(발송 채널 pill "서비스 알림", 알림 제목, 알림 내용, 이동 버튼 안내). 하단 주 버튼 "보낼 내용 확인하기 →", 대상이 0명이면 비활성 "지금은 보낼 대상이 없어요".
- **발송 전 확인은 모달이다** (A08은 페이지였지만 유예·개인 마감을 뺐더니 "대상 n명, 알림 문구, 취소 / 발송하기"만 남는다). 발송 완료 모달은 `A07-notice-sent`: 체크 아이콘, "{n}명에게 안내를 보냈어요", 표(발송 성공 / 발송 실패 / 취업 중 · 제외 / 발송 시각), "제출 현황으로 돌아가기". 확인 모달에도 "대상이 0명이면 발송하지 않아요"와 중복 전송 확인 문구를 둔다.
- **A18 사용자 상세** (`A18-user-record`): 헤더(이름 + login, 요약 한 줄, 오른쪽 주 버튼 "이번 달 서류 검토 →"는 `/submissions`로). 카드 3개(취업 상태 / 받을 계좌 `은행 · •••• 1234`와 통장사본 최종 변경일 / 이번 달 제출 상태). 왼쪽 "검토 및 변경 기록" 표(일시와 제출 월, 처리 내역, 담당자), 오른쪽 "최초 제출 서류" 카드(신분증, 주민등록초본, 통장사본 행마다 teal "열기 ↗" + 안내 문구).
  - **원본 열람 권한**: `operator`, `accountant`만 "열기"가 활성이다. 그 밖의 역할(`admin` 포함)은 "열기"가 비활성이고 "원본은 운영·회계 담당자만 열 수 있어요" 안내가 나온다 (문구는 정했음, final에 없는 화면 문구라 바꿔도 된다). 서버도 매 요청 확인한다.
  - 전체 계좌번호는 어떤 화면 타입에도 두지 않는다. 마스킹 값만 쓴다.
- **서류 검토** (`/submissions/:id`, A02·A03, 2026-10-17): 흐름은 검토 → 승인 전 확인 → 승인 완료, 또는 검토 → 보완 요청 작성 → 요청 완료. 단계는 모달이 아니라 페이지다. 최초(탭 4개)와 월별(탭 1개)은 같은 컴포넌트다.
  - 검토: 사용자 행(이름·login, 취업 상태, 제출 종류·서류 수, 제출·접수 월, 상태 배지) → 서류 탭("현재 보는 서류" / "PDF 첨부됨") → 왼쪽 PDF 영역(파일명, 형식·크기, 다운로드, 확대·축소, 페이지) + 오른쪽 "이 서류에서 확인할 내용"(서류별 정적 체크리스트 3줄, 고용보험은 "{M}월 1일 이후 발급본" 박스와 제출 기간) + 운영팀 메모(학생에게 안 보임) + "보완 요청" / "4종 승인 검토"(월별은 "승인 검토") + 최근 기록 한 줄.
  - PDF 영역은 `app-pdf-viewer`(pdf.js, canvas)가 `GET /api/files/{id}`를 읽어 그린다. 확대·축소와 페이지 이동은 이미지의 컨트롤이다. 원본을 못 여는 역할(admin)은 "PDF는 운영·회계 담당자만 볼 수 있어요" 안내만 본다. 이미지 속 증명서 내용은 디자인 예시라 만들지 않는다.
  - "확인 완료" 배지는 검토 화면에서 그 탭을 열어본 서류에 붙는다 (화면 상태, 서버 저장 아님). 4개 탭을 모두 봐야 "4종 승인 검토"가 활성이다.
  - 보완 사유는 필수·1000자 이하고 학생에게 그대로 보인다. 최초 4종은 "보완을 요청할 서류"를 여러 개 고른다 (`revision_doc_types`).
  - **정책이 이미지와 다른 곳**: 제출 기간은 1일 시작(이미지의 "9월 21일"은 예시)이라 날짜는 cycle 값, 마감은 `lastMoment()`. "기본·승인 유예 기간", "대상자별 유예" 문구는 없앤다. 처리 담당자는 실제 처리한 사람의 역할·이름이다 (이미지끼리 "회계 담당자"/"운영 담당자"가 맞지 않는 건 무시).
- **월별 제출 내역, 사용자 목록**: 이미지가 없다. 제목과 "준비 중" 문구만 있는 placeholder.
- **API 없이 만든다**: 화면은 입력만 받는 순수 컴포넌트고, 미리보기 데이터는 dev 빌드 전용 라우트(`/dev/*`)에서만 상수로 넣는다. 서비스·mock은 없다.

## final끼리 다른 부분

1. **활성 메뉴**: U03-home-due는 진한 teal 배경 + 흰 글자, U03-home-submitted는 연한 mint 배경 + teal 글자다. → **연한 mint로 통일**(2026-10-17 결정).
2. **비활성 메뉴 글자**: home-due는 muted, home-submitted는 ink다. → home-submitted(ink 글자, muted 아이콘)를 따른다. 1번 결정과 같은 이미지를 기준으로 맞췄다.
3. **eyebrow**: home-due는 "U03 / 나의 지원금"으로 화면 코드가 들어가 있다. → "나의 지원금"만 쓴다.
4. **브레드크럼**: home-due는 "나의 지원금 / 동민님, 이번 달 제출 대상이에요", home-submitted는 "나의 지원금 / 홈"이다. → 메뉴명("홈")을 쓴다.
5. **로고**: 사이드바는 큰 ink "OTUS" + 태그라인, U02 상단바는 작은 teal "OTUS", U01은 흰 "OTUS". 화면별로 다르게 쓴다.
6. **"로그아웃"**: U02 상단바에만 있다. 사이드바 화면 상단바에는 없지만 같은 모양으로 넣는다(사용자 결정).
7. **상태 문구**: 배지는 "검토 중", 히어로 pill은 "운영팀 확인 중"이다. 배지는 위 표를 따른다. 히어로 pill은 U03을 만들 때 그 화면 문구를 쓴다.
8. **U02 "임시 저장"**: 파일은 올리는 즉시 draft에 저장된다(api.md). 버튼은 API를 부르지 않고 하단 안내를 "임시 저장됐어요. 다음에 이어서 마무리할 수 있어요."로 바꾼다. 파일이 1개 이상일 때 활성(사용자 결정 2026-10-17).

### A12~A14 자료함·일괄 다운로드 (정책이 이미지와 다른 곳)

- **기본 포함은 이번 달 최종 제출본뿐이다.** 임시 저장(draft)은 어떤 옵션으로도 넣지 않는다. 검토 상태와 상관없이 그 달 최종 제출본은 들어가고, 상태는 `제출목록.csv`에 적는다.
- **승인 안 된 계좌 변경 통장사본**(A12·A13의 "통장사본_검토대기.pdf", "통장 검토 대기")은 쓰지 않는다. 통장사본은 "기본 서류 3종"을 켤 때 그 달에 연결된 **승인된 버전**만 들어간다. A12의 검토 상태는 제출의 상태(`BADGE_LABELS`)다.
- **내려받기는 `accountant`만 한다.** 다른 역할은 자료함을 볼 수 있지만 "선택한 n명 내려받기"와 "내려받기 옵션"이 비활성이고 안내가 나온다 (`canDownloadArchive`, A18의 `canOpenOriginals`와 같은 패턴).
- A12 "동민 자료 보기" 버튼은 이름 셀의 링크(`/users/:id`)가 됐다. 행마다 쓸 수 있고, 아래 버튼 줄이 짧아진다.
- 문구는 A18·A07처럼 해요체다. 이미지의 "~합니다"는 따르지 않는다.
- 라우트: `/archive/:month`(A12), `/archive/:month/options`(A13), `/archive/:month/download`(A14). 활성 메뉴는 "월별 제출 내역"이다 (`roles.ts`의 `also`). 선택한 교육생·옵션은 `core/archive-state.ts`가 세 화면 사이에서 들고 있다.
