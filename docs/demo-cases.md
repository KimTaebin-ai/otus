# 데모 케이스 16종 (case01–case16)

`make demo` / `make seed`가 만드는 시연용 계정이다. 정식 로그인은 42 계정(42 OAuth)뿐이고, 이메일 로그인은 아직 지원하지 않는다. 아래 계정은 평가용으로만 쓰는 데모 계정이다: 데모가 켜진 환경에서만 로그인 화면에 보이는 **데모 로그인 (개발용)** 칸에 데모 아이디를 입력해 들어간다(비밀번호 없음). 이 칸은 운영 환경에서는 보이지 않으며, 정식 로그인과 다르다.
기존 `dongmin`·`seoyeon`과 역할 계정(`opsdemo`·`accountdemo`·`admindemo`)은 건드리지 않으며,
다시 seed해도 이미 있는 계정은 데이터째 건너뛴다(멱등). `make demo-clean`으로 전부 지워진다.

관리자 화면은 학생 앱과 같은 포트에서 서브도메인으로 열린다: **https://admin.localhost:8443**
(학생 앱 https://localhost:8443, `deploy/Caddyfile`의 ADMIN_SITE_ADDRESS 블록이 `/srv-admin`을 서빙).

`admindemo`(관리자) — 학생 계정으로 관리자 API를 부르면 403, 로그인 없으면 401이다.

## case16 중복 차단 시연

최초 4종에는 그달 고용보험가입내역서가 이미 포함돼 있어, 같은 달에 월별(고용보험만)을 또 제출하면 서버가 막는다.

1. 학생 앱의 **데모 로그인 (개발용)** 칸에 `case16`을 입력해 들어간다(데모 환경 전용). 이번 달 접수 기간이 열려 있고, 최초 4종이 검토 대기(제출 완료)로 보인다.
2. 그 상태에서 같은 달 월별 제출을 만들려고 하면(`POST /api/submissions` `{kind:"monthly", target_month:<이번 달>}`) **409**가 돌아온다:

```json
{ "error": { "code": "INVALID_STATE", "message": "이 달은 최초 4종으로 이미 제출했습니다. 같은 달에는 월별 서류를 따로 제출할 수 없습니다." } }
```

3. 거꾸로도 같다: 월별을 먼저 제출한 달에는 최초 4종을 만들 수 없다(메시지만 반대 방향).
4. 반대 종류의 draft만 있는 동안에는 만들 수 있지만, 그 draft의 최종 제출(`finalize`)에서 같은 409로 막힌다. 직원 검토 목록에서는 예전(차단 도입 전) 중복 데이터가 있어도 최초 체인만 보이는 기존 동작이 유지된다.
